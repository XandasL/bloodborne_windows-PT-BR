# Fixes and Issue Analysis

## Date: 2026-09-27

### Issues Under Investigation

1. **Reactivity mask debug overlay not rendering**
2. **Motion trails / ghosting on equipped weapons**
3. **Settings modifications requiring process restart**

---

## 1. Reactivity Mask Setting Persistence

### Root Cause
In `bbport_settings.cpp`:
- `Set()` omitted handling for key `debug_view`
- `Save()` omitted persisting `debug_view` to `bbport.ini`

### Fix
In `gpu/shim/bbport_settings.cpp`:
- Handled `debug_view` in `Set()` with clamping to valid enum ranges.
- Persisted `debug_view` in `Save()`.

---

## 2. Motion Trails on Equipped Weapons

### Diagnosis
Execution logs confirm:
```
Object motion: on (4194304 vertices per frame)
```

Contributing factors:
1. **Subpixel Jitter Configuration:** Jitter was disabled (`jitter=0`) in test configuration, preventing temporal reconstruction. Jitter must remain enabled (`jitter=1`) for FSR 3.1.
2. **Bone Palette Classification:** Weapons and animated props use compact bone palettes (96–384 bytes, 2–8 bones) which were initially filtered out by the bone palette threshold.
3. **Reactivity Mask Exclusions:** The reactivity mask specifically isolates translucent layers (particles, haze) and does not cover opaque meshes like weapon models.

---

## 3. Dynamic Preset Switching & D32S8 Blit Limitations

GPU capability report:
```
GPU scene scaling: AMD Radeon RX 7800 XT (RADV NAVI32) lacks blit support for D32S8
GPU scene scaling: using startup resolution 960x540 for this driver
```

On architectures lacking native Vulkan hardware blit support for combined depth-stencil format `D32_SFLOAT_S8_UINT`, depth buffers are cleared rather than blitted, enabling dynamic resolution switching without process restart.
