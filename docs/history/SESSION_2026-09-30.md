## 1. Two-Stage GPU Command Pipeline

**Problem:** The GPU command thread (`shadPS4:GpuComm`) previously handled PM4 packet decoding, pipeline selection, resource binding, and draw call recording sequentially, leaving secondary cores idle.

**Solution** (`vk_draw_pipe.h`, `vk_rasterizer.cpp`, `liverpool.cpp`):
- **Stage A** (`GpuComm`): Decodes PM4 packets, maintains register state, chooses graphics pipelines, copies small constants into a lockless ring buffer, and queues packets.
- **Stage B** (`bb:DrawRec`): Maintains a local mirror of modified register chunks, binds resources, and records draw and compute dispatch calls into command buffers.
- Communication operates through a 16 MiB lockless ring queue.
- Memory operations (EOP/EOS, WriteData, DmaData, flip signaling) retire on Stage B in strict execution order with draws.

Automatically enabled on systems with 8+ CPU threads (`BB_DRAW_PIPE=0/1`). Yields +32% FPS scaling (83.9 → 110.9 FPS) on 16 threads, and +18% on 8 threads.

## 2. Upscaler Preset GPU Workload Scaling

On Radeon RX 7800 XT, native 1080p scene rendering consumed 3.67 ms, while FSR 4 reconstruction took ~1.4 ms. Two bottlenecks were addressed:
1. **Lighting Passes Rendered at 1080p:** Render target eligibility checks inspected all 8 MRT slots rather than the active draw slots, catching G-buffer textures read by the shader. Corrected via Toggle 47.
2. **Redundant Resampling:** Each pass reading a downscaled target previously performed a stretch blit back to 1080p. The shader recompiler now identifies targets sampled exclusively via normalized UVs, reading downscaled copies directly.

## 3. Stability: Resolving Heap Corruption Crash

**Root Cause:** Stage A previously issued the "GPU idle" interrupt as soon as PM4 command buffers were unpacked. `sceGnmSubmitDone` unblocked the game process, allowing it to free heap memory containing EOP fence markers that were still pending execution on the Vulkan recording worker.

**Resolution:** Stage A now flushes the command pipeline and synchronizes pending markers before signaling idle interrupts. Consecutive 30-minute soak tests completed without crashing.

## 4. High-Resolution Display Output (1440p / 2160p) & Modular Game Effects

- **Display Resolution** (`bbport.ini`: `output_res=2560x1440` or `3840x2160`): Internal 3D scene renders at preset fraction, FSR 3 / FSR 4 upscales to output target, and UI elements rasterize directly at native display resolution.
- Direct memory budget scaled via `BB_DMEM_MB` (default 5056 MiB, elevated to 9152 MiB for 4K).
- Modular game effect toggles (`patches/Bloodborne.xml`): chromatic aberration, DoF, motion blur, SSAO, native game AA, dynamic point shadows, SSR, intro skip, model LOD (-2 to 2).
